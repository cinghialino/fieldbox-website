How Fieldbox actually keeps your files safe

How verification works

Think of it like a wax seal on a letter. The seal is made from the exact contents of what's inside, so if a single word changes, the seal no longer matches. Fieldbox does the same thing with a mathematical fingerprint (the technical name is SHA-256) instead of wax.

  1. Fieldbox reads the file straight off your card and calculates its fingerprint.
  2. It copies the file onto your device.
  3. It reads the copy back and calculates the fingerprint again.
  4. The two fingerprints are compared. If they match exactly, the file is marked verified. If they don't, Fieldbox retries the file once before flagging it as failed.

This happens for every single file in the transfer, not a sample. The green "all files verified" screen only appears once every fingerprint on the card matches its counterpart on your device. A file can only pass this check once every fingerprint has actually been compared and matched.

How Fieldbox confirms a cloud backup really landed

Uploading a file and having the upload finish without an error isn't proof the file is intact, connections drop, bytes get corrupted along the way, and a naive app would show "done" anyway. Fieldbox checks this properly, in two separate steps.

  1. The cloud checks its own math. When Fieldbox uploads a file, it sends the fingerprint along with it. Your cloud provider recalculates the fingerprint from the bytes it actually received and rejects the upload outright if they don't match. A corrupted upload can't be silently accepted.
  2. Fieldbox checks back afterward. Once the upload finishes, Fieldbox asks the cloud a separate question: is this exact file really sitting there, at the right size, with the right fingerprint? Only a yes to all three counts as confirmed.

A cloud backup only shows as confirmed once both checks pass for every file. That is the standard behind the green cloud status you see in Fieldbox.

Why a file sometimes takes a few minutes to show up in your cloud provider's own website

Some providers' web file browsers take a little while to catch up after an upload, that's just how their listing pages work, not a sign anything is wrong. Fieldbox's confirmation check asks about that one specific file directly, so it gets a reliable answer the moment the file lands, even before the provider's own website has caught up.

How shared cloud accounts stay safe

Handing a whole crew the same cloud login sounds risky, one careless tap could wipe out someone else's only copy of a shoot. Fieldbox is built so that can't happen. Sharing an account this way is part of the Pro plan.

Every device that connects to a shared account gets its own private space inside it. Two photographers can use cameras that happen to produce identically named files and they'll never collide or overwrite each other. Everyone on the team can browse everyone else's galleries from the in-app Cloud Browser, which is useful for a producer keeping track of a whole shoot, but a device can only ever delete the files it personally uploaded. Try to delete someone else's session and Fieldbox shows a lock instead of a delete option.

So the account can be fully shared without the risk being shared too. Everyone sees the same pool of work, but nobody can accidentally erase a colleague's backup.

What happens when a transfer is interrupted

Whether you tap "interrupt" yourself, close the app, unplug the reader, or the battery dies, Fieldbox never leaves things in a confusing state.

Whichever file is actively copying when the interruption happens is either finished safely first or thrown out entirely, it is never left half-written on your device. Every file after that point in the transfer is simply marked as not yet copied. Nothing on the card is touched, and nothing already verified is redone.

The screen tells you plainly how many files made it in before stopping, and shows a standing warning not to format the card until the rest are backed up. Plug the card back in whenever you're ready, and Fieldbox picks up exactly where it left off, skipping everything that's already confirmed and only copying what's left.
