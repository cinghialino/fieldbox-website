Why Fieldbox Is Better Than Copying a Card in Files

Files can put a second folder on your iPhone or iPad. Fieldbox tells you whether the shoot was copied correctly and where the complete copies are now.

Alessandro CasagliSeptember 1, 20264 min read

The Files app can copy a memory card. Connect a reader to an iPhone or iPad, choose the files, pick a destination, and let the copy run. What Files does not give me is a backup record for the shoot.

After a long transfer, seeing a folder at the destination is not the answer I need. I want to know whether every file arrived, whether the copied bytes match the card, whether anything failed, and whether another complete copy exists somewhere else. I do not want to work that out by comparing folders, counting files, and opening several storage apps.

That is why I built Fieldbox.

Files completes a copy operation. Fieldbox accounts for the shoot.

A file has to prove it copied correctly

Fieldbox does not put a file into its archive simply because a copy operation finished. It first copies the file into a staging area. It calculates a SHA-256 hash from the source and another from the staged copy, then compares them. Only a match is promoted into the archive.

If the hashes do not match, Fieldbox retries the file once. If it still does not match, the file is reported as failed. There is no vague middle ground where a file appears to be present and the rest is left to assumption. Every attempted file gets an outcome.

The original card remains untouched throughout the process. Fieldbox does not write to it, erase it, or format it. The card stays as one copy while the verified files become another copy on the device.

The shoot stays together

A camera card is not just a pile of unrelated files. It represents a shoot, a day, or a part of a job. Fieldbox keeps that transfer together as a session, with its own identity, file manifest, and results.

That matters as soon as there is more than one card or more than one destination. A folder name tells me where I put something. A Fieldbox session tells me what was selected, what copied, what matched, and what needs attention. I can return later without reconstructing the transfer from filenames and memory.

The archive is separate from everyday file handling

Files is built for handling documents: browsing, moving, renaming, sharing, and deleting. Those are useful actions, but they are the opposite of what I want inside a backup archive.

The Fieldbox archive is app-managed and cannot be edited in Files. That boundary keeps routine file handling away from the verified archive. When I need to use an image somewhere else, Fieldbox Pro can create a separate working copy for Photos, Files, or another app. It can also export a session to an attached USB-C drive for a client handoff. The archive remains the archive.

One session can upload to several destinations at once

With Fieldbox Pro, the same session can upload to multiple selected cloud or NAS locations concurrently. Each destination gets its own upload lane, so one provider does not have to finish before the next one starts. I can begin building separate offsite copies without sending the shoot through the same manual process again and again.

Fieldbox tracks every destination independently. A failed or incomplete upload to one location does not erase the progress of another, and partial coverage is never presented as a complete offsite copy.

The evidence depends on what each storage provider reports. Some providers return a checksum that Fieldbox can compare. Others confirm that the object exists with the expected size. Fieldbox shows the distinction instead of presenting every provider result as the same kind of proof.

Backup Status brings the current inventory together. It shows whether the device still has every verified file and whether a complete session is confirmed on the configured destinations. It is a view of the copies that exist now, not a certificate or a guarantee about the future.

Restoring a file is also verified

If a file has been removed from the device, Fieldbox can restore it from the original card or a confirmed provider. The returning file goes through staging again. It only re-enters the archive after its SHA-256 matches the source hash recorded for the session.

That is the reason Fieldbox is better than copying a card in Files for this job. It does not stop when another folder exists. It verifies the transfer, keeps the shoot together, follows complete copies across destinations, and applies the same check when a file comes back.

Files moves files. Fieldbox tells me what happened to the shoot.
