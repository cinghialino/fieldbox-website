Field Notes · Transfer design

Choose First, Then Copy

A memory card is not always one indivisible job. Fieldbox makes selection a deliberate step between understanding the source and moving files into the archive.

Alessandro CasagliAugust 25, 20266 min read

The simplest transfer model treats a card like a sealed box: choose the source, copy everything, wait for the result. That model works until the card contains more than one useful boundary.

A photographer may have several days on one card. A drone operator may need only the current flight. A video card can contain finished takes beside material that should stay out of the present session. Copying the entire source can be unnecessary, but choosing files before the source has been fully scanned can hide what is being left behind.

First understand the source. Then choose the scope. Only then begin the transfer.

Scanning and selecting answer different questions

A scan answers, “What is on this source?” Selection answers, “What belongs in this transfer?” Combining those questions too early makes it difficult to distinguish an undiscovered file from a deliberate exclusion.

Fieldbox scans the chosen source without modifying it, then presents the files by capture date. The date groups make a large source easier to review. They do not decide what must move.

From that overview, an entire date can be selected at once. Opening a date reveals the individual files inside it, so the scope can be narrowed further. Select All remains available when the whole card really is the job.

Selection is intent, not evidence of success

A checked file has been chosen. It has not yet been copied or verified. Keeping those states separate avoids giving the selection screen more authority than it has.

Once the transfer begins, Fieldbox copies the selected files to staging on the device. It reads the source and staged copy, calculates a SHA-256 value for each, and accepts the local file into the app-managed archive only when the values match.

A file left outside the selection has another clear outcome: excluded from this transfer. It is not counted as a transfer failure, and Fieldbox does not describe it as verified.

  • Selected means included in the transfer plan.
  • Excluded means not part of this transfer.
  • Verified means the measured source and local SHA-256 values matched.
  • Fieldbox never writes to, erases, or formats the original card.

The structure should survive the transfer

A useful review should not disappear the moment copying starts. Fieldbox carries the date organization into the completed session, where imported files are grouped by capture date.

Each file also shows its recorded size and import date. Those details answer different questions. Capture date connects a file to the work that produced it. Import date records when it entered this Fieldbox session. Size provides a concrete way to distinguish and account for the file.

The result is not only a cleaner browser. It is continuity between the choice made before the transfer and the record available afterward.

Why dates are a useful first boundary

Dates are imperfect. A camera clock can be wrong, a shoot can cross midnight, and multiple assignments can happen on the same day. They are still a useful first view because they reduce a long, flat list into recognizable groups without forcing a hidden decision.

The important part is that the group remains navigable. A date can be selected as a whole when it matches the job, or opened when it does not. The interface offers a shortcut without turning that shortcut into a rule.

A useful default reduces work while preserving the ability to inspect and change the decision.

The source remains the source

Selective Transfer changes the scope of a session, not the source card. Fieldbox reads the selected source and leaves its lifecycle under the user’s control. It does not erase, format, write to, or automatically eject the card.

This boundary matters even more when only part of a card is selected. Leaving files out of one transfer is not a command to remove them from the source. It is only a decision about what Fieldbox should copy and verify now.

The boundary of the claim

Selective Transfer makes the intended scope explicit. It does not guarantee future file availability or make an unselected file part of the archive. Verification applies only to files that were copied and whose measured source and local SHA-256 values matched.

A smaller transfer can still have a complete explanation

“Copy less” is not the whole design goal. The stronger goal is to make a smaller transfer as legible as a full-card transfer.

The scan shows what was available. The selection records what was intended. The transfer measures what succeeded. The completed session keeps the files organized so that decision can be understood later.

The transfer does not need to include the whole card. Its explanation should still be whole.
