The Threshold of the Archive

Copying produces another file. Verification is what allows Fieldbox to accept that file into the archive. Keeping those two moments separate became one of the app’s earliest design decisions.

Alessandro CasagliJune 19, 20267 min read

A progress bar has a seductive simplicity. Bytes move from left to right, the bar reaches the end, and the transfer looks complete. But the end of a copy operation answers only one question: did the operating system finish writing something at the destination?

Fieldbox needed to answer a stricter question: do the bytes written on the iPhone or iPad match the bytes that were read from the source?

The difference between those questions created a threshold. Before that threshold, a file is an attempted copy. After it, the file can become part of the archive.

The archive is not where a copy is being made. It is where a verified copy is admitted.

Staging keeps uncertainty in the right place

Fieldbox does not write an incoming file directly to its final archive path. It first writes the file into a staging area. Staging is deliberately temporary: it is a place for bytes whose status has not yet been decided.

Once the copy is there, Fieldbox calculates SHA-256 from the source and from the staged local file. If the values match, the staged file crosses the threshold and is promoted into the app-managed archive. If they do not, Fieldbox removes the staged attempt, retries once, and leaves a persistent failure outside the archive.

01ReadRead the selected source file without changing it.
02StageCopy the bytes into temporary local storage.
03CompareCalculate and compare source and staged SHA-256 values.
04PromoteMove the file into the archive only after a match.

This structure prevents a half-written or unchecked file from occupying the same conceptual space as an accepted one. The distinction exists in storage, in the transfer record, and in the language the interface uses.

Interruption becomes a state, not a catastrophe

Working away from a desk is full of interruption: a reader is unplugged, an app is closed, a device runs low on power, or someone simply needs to stop. If the archive were treated as one large all-or-nothing transaction, an interruption could erase the meaning of everything completed before it.

Fieldbox instead makes the decision file by file. A file that already crossed the threshold remains a verified archive file. A file still in staging has not crossed it. Files that were never reached remain on the source and remain outstanding.

That gives a partial transfer a precise meaning. It is not “complete enough,” and it is not a total failure. It is a recorded set of verified files alongside a recorded set that still needs attention.

The same threshold applies on the way back

Restore could have been treated as a special case. A provider had already accepted an uploaded object, so a successful download might appear sufficient to put the file back.

But a restore is another arrival of bytes, and the archive threshold should not depend on which direction they traveled. Fieldbox downloads a restored object into separate staging, calculates its SHA-256, and compares it with the original source-derived value recorded in the manifest. Only a match allows it back into the archive.

Provider confirmation and restore verification therefore answer different questions. The first describes evidence returned by the destination. The second measures the bytes that have just arrived on the device.

The cost is intentional

Reading both source and staged data takes time and energy. Staging also needs temporary space. A design optimized only for apparent speed could remove one of those reads or display success as soon as copying ends.

Fieldbox accepts the extra work because it makes the archive’s meaning simpler. There is no provisional category hidden inside it. Either a file passed the admission comparison or it did not.

Later checks still matter. Files can be deleted or changed after import, devices can fail, and no local comparison promises future availability. The threshold does not make the archive permanent. It makes the original admission decision measured and explainable.

The boundary of the claim

Archive promotion means that Fieldbox measured matching source and staged-copy SHA-256 values before accepting the file. It does not guarantee that the file will remain available, unchanged, or recoverable later.

A small rule with wide consequences

“Promote only after verification” began as a storage rule, but it shapes much more than storage. It determines what an interruption means, which files appear in a verified manifest, how restore works, and why a success screen cannot be driven by a copy counter alone.

Most importantly, it prevents Fieldbox from borrowing certainty from an operation that did not provide it. Copying moves bytes. Comparison establishes whether the two measured versions matched. The archive begins only after the second statement is true.
