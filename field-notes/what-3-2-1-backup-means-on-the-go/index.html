What 3-2-1 Backup Means While on the Go

One copied card can solve an immediate problem while leaving several others untouched. A 3-2-1 approach spreads a complete session across three copies, two kinds of storage, and one location somewhere else.

Alessandro CasagliAugust 25, 20266 min read

Making another copy is valuable. It means a damaged card does not automatically remove the only instance of the work. But two copies kept together can still share the same failure: the same lost bag, stolen vehicle, damaged device, or unavailable location.

The 3-2-1 approach is a compact way to think beyond a single failure. It is not tied to one app, provider, or profession. It describes how copies are distributed.

Three complete copies. Two kinds of storage. One complete copy kept somewhere else.

Three means three complete copies

A thumbnail, partial upload, or folder containing only some of the session does not carry the same value as a complete copy. Each location counted by Fieldbox must be able to account for every verified file in that session.

Files spread across several incomplete providers do not combine into one complete location. A provider counts only when it has confirmed the complete session.

Two means different storage types

Multiple copies on one device can disappear together. The “2” asks for copies across at least two kinds of storage so that one device-level problem does not reach every copy in the same way.

For a new Fieldbox session, the original card, the verified archive on an iPhone or iPad, and a complete cloud or offsite NAS copy create the clearest path. The source and device are physically distinct, while the remote location adds another storage boundary.

One means somewhere else

An offsite copy is separated from the cards and device. Internet cloud providers count as offsite. A WebDAV or NAS location counts only when the user identifies it as living somewhere else, such as a studio or another building.

A NAS in the same room can still be a useful additional copy. It does not satisfy the offsite part simply because it is a server.

Before reusing the card

Card + device + offsite

The complete original source, every verified file on this iPhone or iPad, and one complete confirmed offsite location.

After the source is unavailable

Device + two locations

The complete device archive and two independently confirmed complete locations, with at least one kept offsite.

The source card has a changing role

Before it is reused, the source card can count as one complete copy. Fieldbox bases that status on the latest recorded complete import or scan. Once the card is disconnected, the app cannot continuously observe what remains on it.

If the user later marks that source formatted, Fieldbox records the statement as a user assertion and stops counting the source as a current complete copy. The app does not format the card itself. To meet the 3-2-1 conditions afterward, the device copy needs two independently confirmed complete locations, including at least one offsite.

Why current inventory matters

A session can meet 3-2-1 today and fall short later. A local file can be removed, a provider can stop confirming a complete session, or the original source can be reused. A badge that never changes would describe history, not the copies available now.

Fieldbox therefore treats Backup Status as a current inventory. It evaluates whether every verified file remains on the device, whether a complete confirmed location is offsite, and whether three current complete copies exist across the required storage boundaries.

  • A partial location remains visible but does not count as a complete copy.
  • At least one complete confirmed location must be offsite.
  • Marking a source formatted is a recorded user assertion.
  • The status can change when the current copy inventory changes.

What 3-2-1 does not promise

The approach reduces dependence on one card, device, storage type, or location. It does not certify that files are permanent, guarantee recovery, or make every future event predictable.

Its value is practical: a problem affecting one copy does not automatically become a problem affecting all of them. The status is most useful when its requirements stay concrete and its limits remain visible.

The boundary of the claim

A Fieldbox 3-2-1 status reports the session’s current recorded copy inventory. It is not a certificate or guarantee. Provider confirmations describe what each destination reported, and source availability remains tied to the latest recorded observation or user assertion.

3-2-1 is not the end of a progress bar. It is a way to avoid asking one copy to survive every problem.
