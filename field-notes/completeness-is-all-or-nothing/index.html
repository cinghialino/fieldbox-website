Completeness Is All or Nothing

Partial copies are valuable and worth showing. But if no single location contains the whole session, Fieldbox cannot honestly count one complete copy there.

Alessandro CasagliJune 22, 20268 min read

Imagine a session with three cards. The first has reached one provider, the second has reached another, and the third is still only on the device. Every file may exist somewhere, yet no provider can return the session on its own.

It is tempting to add those fragments together. The arithmetic reaches 100 percent, but the operational reality does not. If either provider becomes unavailable, the assembled whole disappears with it.

That distinction produced one of Fieldbox’s central accounting rules: a copy has to exist as a complete, independently usable unit before the app counts it as one copy.

Coverage can be partial. A complete copy cannot.

The location has to stand on its own

Fieldbox evaluates each configured destination separately. A provider counts as a complete copy only when that provider has confirmed every transfer in the session using the evidence method available for that service. To satisfy the offsite leg, that complete provider must also count as offsite; a same-site destination can be complete without being offsite.

This remains true even when multiple partial providers collectively contain all the files. They are still useful destinations. Fieldbox shows their progress and names what each one holds. It simply does not invent a complete provider that does not exist.

The labels in that example are intentionally unglamorous. Partial does not mean useless, and complete does not mean permanent. They describe coverage of the session as Fieldbox currently records it.

The active destination is not the truth

An early interface risk was tying backup status to whichever destination happened to be selected for the next upload. That would make a completed copy appear to vanish when someone switched to another provider.

The accepted rule looks across every connection instead. If one provider holds the whole session, Fieldbox can name it as complete regardless of which destination is active now. Upload intent and current copy inventory are separate facts.

The same principle reaches back to the source

Source coverage introduced a continuous measurement into the same model. A later complete, read-only scan might observe 811 of 824 originals previously attributed to one source. Reporting 98.4 percent is more informative than reducing the source to “present” or “missing.”

But the copy count remains binary. If thirteen attributed originals are absent from that observation, the source cannot reconstruct the session inventory it is supposed to represent. It remains a valuable partial source, but it does not count as one complete current copy.

This later source model did not change the earlier completeness decision. It applied the same principle to better evidence: show the fraction, but count a copy only when the location stands on its own.

Three, two, and one are outputs

Fieldbox uses complete copies to evaluate its defined 3-2-1 inventory. The device must currently hold every verified file. At least one complete confirmed provider must be offsite. The third current copy comes from either the complete source or, after the user marks the source card as formatted, a second independently confirmed provider.

Those conditions are not a slogan applied after the fact. They are outputs of the copy inventory. If a local file disappears, source coverage becomes partial, or provider coverage no longer spans the whole session, the assessment changes.

  • The device holds every verified file.
  • At least one complete confirmed provider is offsite.
  • A third complete current copy is independently accounted for.

Why the strictness matters

A more generous interface could award reassuring badges sooner. It could add provider fragments together, count a mostly complete card, or preserve a green state from an earlier success screen. Each shortcut would make the display easier to satisfy and harder to defend.

The stricter rule can mean waiting longer for a complete state. It can also expose inconvenient gaps. That is the point. Fieldbox is most useful when it distinguishes progress from completion rather than allowing one to impersonate the other.

The boundary of the claim

A complete copy means the current Fieldbox inventory attributes the whole verified session to one independently usable location under its recorded evidence method. It does not guarantee that the location will remain available or that provider confirmation proves permanent integrity.

Completeness is deliberately boring

There is no confidence score and no weighted average. A location either contains the whole inventory or it does not. The surrounding evidence can be rich, with percentages, timestamps, and provider methods, while the final unit stays simple.

That simplicity makes the rest of the product easier to reason about. One provider means one provider. One source means one source. One copy means the entire session exists there, not that its pieces could theoretically be gathered from several places if every dependency cooperated.
